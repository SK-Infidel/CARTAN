# GeoMind Architecture

> **GeoMind v2** — native 992D multi-decomposition E8 engine.

## Overview

GeoMind is a hybrid language model whose token representations live on the **E8 Lie algebra manifold** — a 248-dimensional space that is the unique exceptional Lie group of rank 8 and dimension 248. Unlike standard transformers that process tokens as arbitrary points in ℝⁿ, GeoMind tokens are **phase space points** on a Sasaki-lifted fiber bundle, governed by wave equations and symplectic geometry.

As of v2, GeoMind processes tokens across **four simultaneous algebraic views** of the E8 manifold, giving an effective internal state of **992 dimensions** at every layer.

## The E8 Manifold

The E8 root system has exactly 248 vectors that decompose into three sectors:

| Sector | Count | Role in GeoMind |
|--------|-------|-----------------|
| Cartan subalgebra | 8 | Position coordinates (diagonal generators) |
| Integer roots ±eᵢ±eⱼ | 112 | Routing/attention keys |
| Half-integer roots (±½,…,±½) | 128 | Memory values (payload) |

The 248D E8 Lie algebra is generated by these 240 root vectors plus the 8 Cartan generators, giving the **adjoint representation** of E8.

## v2: Four Parallel Decomposition Streams (992D)

The core insight of GeoMind v2 is that the 248D E8 space admits multiple **non-overlapping algebraic decompositions** — mathematically distinct ways to partition the same space that emphasize different algebraic structures.

GeoMind v2 runs all four simultaneously:

| Stream | Decomposition | Sub-sectors | Total |
|--------|--------------|-------------|-------|
| 0 | **SO(16)** | 8 (Cartan) + 112 (integer) + 128 (half-integer) | 248 |
| 1 | **E7 × SU(2)** | 133 (E7 adj) + 3 (SU(2) adj) + 112 (fundamental) | 248 |
| 2 | **E6 × SU(3)** | 78 (E6 adj) + 8 (SU(3) adj) + 81 + 81 (fund/conj) | 248 |
| 3 | **SU(9)** | 80 (adj) + 84 (anti) + 84 (conj) | 248 |
| | **Total native state** | | **992** |

Each stream receives the same 248D embedding output, applies a learnable **basis-change matrix** (initialized to identity), then processes independently through its own set of 24 blocks. 

*Performance Note:* As of the latest update, the four independent streams are processed in true hardware parallel using explicit `torch.cuda.Stream` asynchronous execution queues, ensuring full GPU SM utilization rather than sequential bottlenecking.

Every `HERALD_EVERY = 6` blocks, a lightweight cross-stream attention pass lets the four views communicate. After all 24 blocks, the four streams are fused back to 248D for the output head.

```
Token → E8SasakiEmbedding (248D)
                ↓
        E8DecompSplitter (248D → 4 × 248D)
                ↓
  ┌─────────────────────────────────────────┐
  │ Stream 0: SO(16)    ──→ 24 blocks ──→ 248D  │
  │ Stream 1: E7×SU(2)  ──→ 24 blocks ──→ 248D  │
  │ Stream 2: E6×SU(3)  ──→ 24 blocks ──→ 248D  │
  │ Stream 3: SU(9)     ──→ 24 blocks ──→ 248D  │
  │       ↑ herald every 6 blocks ↑             │
  └─────────────────────────────────────────┘
                ↓
        Fusion: Linear(992, 248) + RMSNorm
                ↓
        LM Head (tied to embedding weights)
```

## Byte Coordinate Encoder (BCEN) Embedding

GeoMind v2 uses a completely **open-vocabulary** continuous coordinate architecture, replacing discrete token embedding tables with the **Byte Coordinate Encoder (BCEN)**. Text is processed as space-delimited byte sequences (up to 16 bytes per segment), mapped directly to the 248D E8 manifold.

```text
Byte Sequence (up to 16 bytes)
   ↓  BCEN (~270K params): Fourier feature projection
   ↓  continuous coordinate [248D]
   ↓
   ↓  to_tangent_proj: Linear(248, 7)    [directional context]
   ↓  drift_rnn:       GRU(7 → 64)       [context-dependent 1-form b]
   ↓  b_proj:          Linear(64, 7)
   ↓
15D Sasaki point (x ∈ E8, ẋ ∈ TₓE8)
   ↓  geometric_lift: Linear(15, 248)
   ↓  fiber_connection: Linear(7, 124) → U(1)^124 phase rotation
   ↓
248D E8 state  →  DecompSplitter  →  4 × 248D
```

This mapping eliminates the legacy 49.6M parameter `token_to_roots` embedding table. The lightweight BCEN (~270K parameters) learns the topology of byte sequences, projecting them into Fourier-basis continuous coordinates.

The **fiber connection** implements a gauge twist: each coordinate's 7D tangent vector generates 124 complex phase angles that rotate the base 248D state as a U(1)¹²⁴ gauge transformation. This encodes directional geometry (the path from one point to the next matters, not just the positions).

The **drift RNN** maintains a 1-form `b` (the Randers warp field) that makes distances asymmetric: the cost of going from state A→B differs from B→A. This models the intrinsic directionality of language.

## Output & Coordination Mapping

After processing through the E8 block layers, GeoMind does not use a massive `vocab_size` logit head. Instead, it predicts the next continuous coordinate directly:

```text
248D E8 Fused State
   ↓
E8CoordPredictionHead (Linear projection)
   ↓
Continuous Predicted Coordinates [B, L, 248]
```

To convert these predicted continuous coordinates back into text, GeoMind utilizes an **InverseBCEN** (~390K params) which is a decoder model. However, during live generation, it relies on a faster database-backed lookup.

## SQLite Registry & Snap-to-Lattice

During generation, the predicted 248D coordinate could theoretically represent an infinite spectrum of meaning. GeoMind uses `checkpoints/geometry_registry.db`—an SQLite-backed **SemanticLattice**—to snap coordinates to known byte-sequences in $O(1)$ time.

* **Backward-Compatible Lookups**: Existing lattice checkpoints seamlessly migrate to the database.
* **Zero-Day Concept Registration**: New terms can be injected directly into the SQLite database without retraining the model. The model's coordinate-space geometry naturally integrates new vocabulary points.

## Pure Differential Geometry & Cognitive Metacognition

GeoMind v2 has completely eradicated standard deep-learning Euclidean assumptions (like `LayerNorm`, $L^2$ weight decay, MSE loss, and global gradient clipping) in favor of pure, unbounded Finsler geometry:

1. **RMSNorm & Preservation of Drift**
   Instead of subtracting the mean via `LayerNorm` (which mathematically erases the critical phase drift $\beta_{drift}$), GeoMind uses `RMSNorm`. This preserves the momentum of the wave equation without artificial centralization.
2. **Adaptive Gradient Clipping (AGC)**
   Global Euclidean gradient clipping shrinks the structural magnitude of the manifold. GeoMind uses layer-wise AGC, which dynamically bounds the gradients relative to the physical Frobenius norm of each specific layer, preventing structural collapse while guarding against mathematical explosions.
3. **Self-Reflective Predictive Coding (Inherent Self-Awareness)**
   A `surprise_head` predicts the Finsler-Randers distance (the "surprise") between its own prediction and the true target. The network physically learns from the L1 absolute difference between its predicted surprise and actual surprise, creating a `surprise_state` feedback loop without generating violent quadratic (MSE) gradients.
4. **Cognitive Backtracking (Phase 3 Simulated Annealing)**
   During text generation, if the predicted surprise exceeds a threshold, the model samples multiple candidates from the SemanticLattice. The backtracking loop injects dynamic mathematical noise using a **Simulated Annealing** schedule.
5. **Epiphany Reward & Complacency Penalty**
   The model is actively rewarded for sudden drops in actual surprise ($\max(0, S_{t-1} - S_t)$). To prevent the model from settling into a safe "complacent" minimum, a linear loss penalty is applied the longer it stays plateaued, forcing it to seek out a new epiphany along the geodesic path.

## Block Types

Each stream processes tokens through 24 interleaved blocks in the pattern:

```
[cosformer, ssm, spectral, dual_routed, spectral, ssm] × 4
```

### E8CosformerAttention
**O(N) causal linear attention** with E8-structured routing.

- **Q/K** from integer root sector (112D) — the routing space
- **V** from half-integer root sector (128D) — the memory payload
- **Randers drift** modifies K via the Cartan coordinates (8D), making key matching directionally asymmetric
- **Sasaki Reeb field** modulates Q for invariance-preserving attention
- Cosine re-weighting enforces local context bias essential for mathematical reasoning

### E8LatticeWaveSSM
**Wave propagation on the E8 root graph.**

Simulates the pure discrete wave equation on the E8 lattice adjacency graph:
```
v_{t+1} = tanh(0.9·v_t - 0.05·L·ψ_t + W_f·x_t)
ψ_{t+1} = tanh(ψ_t + 0.2·v_t)
```
where L is the normalized E8 graph Laplacian. Token representations propagate as waves across the lattice topology. The wave relies strictly on physical velocity limits (`tanh`) and structural damping (`0.9`), eliminating the need for artificial statistical normalization (`RMSNorm` or `LayerNorm`) inside the unrolled recurrence, making it mathematically unconditionally stable.

### SO16SpectralMemoryHybrid
**FNet-style spectral mixing with 4096D FFN expansion.**

Applies a real DFT over the first 16D (SO(16) Cartan subspace), then expands through a wide FFN:
```
fft_mix = DFT_16×16 · x[:16]      [spectral mixing over SO(16)]
output  = x + FFN(fft_mix)        [residual: 16D → 4096D → 248D]
```
The 8 spectral blocks contain the majority of the model's processing parameters (~1.08M each) due to the 4096D expansion.

### E8DualRoutedAttention
**Hardcoded dual-sector routing.**

Explicitly routes information through the E8 algebraic structure: integer roots for routing/keys, half-integer roots for memory/values. No O(N²) attention — uses linear operations over the two sectors with KV caching for O(1) per-step generation.

## High-Performance Checkpoint Decoupling

Because GeoMind models maintain massive internal structures like the `SemanticLattice` and Phase 3 moving-average contexts, a unified checkpoint file could exceed 1.78 GB, creating immense I/O bottlenecks during frequent saves. 

To prevent GPU starvation, GeoMind utilizes a **decoupled checkpoint architecture**:
1. **`e8_agent_model.pt`**: Contains only the neural network weights and training context. Saved frequently (e.g., every 200 steps).
2. **`e8_agent_optim.pt`**: Contains the optimizer, scaler, and scheduler momentum. Saved periodically (e.g., every 1000 steps).
3. **`e8_agent_lattice.pt`**: Contains the massive 100,000+ entry `SemanticLattice`. Saved periodically (e.g., every 1000 steps).

## E8 Geometry: Why It Works

The E8 root system has extraordinary properties that make it ideal for representation learning:

1. **Kissing number 240**: Every E8 root has exactly 56 nearest neighbors — the most tightly packed lattice in 8D. This means the routing structure is maximally efficient.

2. **Unimodularity**: The E8 lattice is self-dual (E8* = E8). The embedding and output head use the same weight matrix (tied weights), which is geometrically consistent — the space "speaks" the same coordinate system it "hears."

3. **Exceptional nature**: E8 cannot be embedded in a simpler group — it is the largest exceptional Lie group, with no analogue in any family (A_n, B_n, C_n, D_n). This algebraic uniqueness provides a rigid geometric backbone that constrains the representation space in ways that arbitrary high-dimensional spaces do not.

4. **The four decompositions** (v2): Each decomposition (SO(16), E7×SU(2), E6×SU(3), SU(9)) is a maximal subgroup of E8 — the largest possible subgroup that still fits inside E8. Running all four forces the model to learn representations that are simultaneously coherent under multiple maximal symmetry breakings, analogous to learning invariants under multiple group actions simultaneously.

## Knowledge Assimilation Architecture

Unlike traditional LLMs which learn vocabulary statistically over billions of tokens, GeoMind leverages its geometric backbone to directly ingest and assimilate knowledge from fully-trained Teacher LLMs (such as Llama-3 or Gemma) without destroying the existing semantic lattice.

The old RIF (Representational Isomorphic Fusion) loss-based alignment has been replaced with a **3-Phase Deterministic Geometric Pipeline**:

1. **SVD Extraction (`extract_teacher_weights.py`)**
   The static Euclidean embedding matrix is extracted from the HuggingFace teacher model. 
2. **Orthogonal Procrustes Alignment (`assimilate_weights.py`)**
   The massive teacher space is compressed into GeoMind's 248D latent space via Singular Value Decomposition (SVD). The pipeline queries the `geometry_registry.db` for common WordNet anchors and applies an **Orthogonal Procrustes Rotation** to mathematically spin the teacher's vector space until it perfectly overlays the GeoMind crystalline lattice. The rotated un-shared vocabulary (e.g., slang, coding keywords, unique grammatical tokens) is mathematically snapped to the nearest valid $E_8$ coordinates and injected directly into the registry.
3. **BCEN Addition (`train_assimilated.py`)**
   Supervised Fine-Tuning is run exclusively on the `ByteCoordinateEncoder`. This mathematically "adds weight" to the input network, teaching it to map new byte-sequences to their newly determined spatial coordinates without destabilizing the core routing blocks.
