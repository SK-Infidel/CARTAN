## Enum vs Array Memory Layout Mismatch in AST Passes
- **Status**: Identified
- **Root Cause**: parser.car was refactored to use enum Stmt and enum Expr instead of array-based AST nodes. In cartanc_rust.exe, enum variants (Expr::EnumInit) allocate memory via malloc(size) and store the tag at offset 0, followed by fields at offset 8, 16, etc. They do NOT include a hidden length header. However, llvm_codegen.car and main.car are still using cartan_tree_get_f32(stmt, X) or array indexing stmt[0] to access these enum variants. Since cartan_tree_get_f32 expects a length header, it adds 1 to the index (ptr[idx+1]). This causes cartan_tree_get_f32(stmt, 0.0) to read offset 8 (the first field) instead of offset 0 (the discriminant tag).
- **Effect**: Memory corruption and broken code generation. Pointers are incorrectly interpreted as discriminants, leading to random behavior, skipped generation loops, and crashes during LLVM IR generation.
- **Fix Required**: Update all accesses to stmt and expr fields in llvm_codegen.car, main.car, and 	ype_checker.car to use cartan_get_enum_field(ptr, idx) for doubles and cartan_enum_get_ptr(ptr, idx) for pointers, which correctly map directly to ariant[idx] without adding the length header offset.
